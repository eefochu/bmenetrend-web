# BMenetrend Web

This repository is the web version of BMenetrend, the Android transit app in `../bmenetrend` (locally `~/Stuff/Code/Projects/bmenetrend`). Treat the Android implementation as the product and data-contract reference. Implement web equivalents of its behaviour and use the same existing backends; do not build an unrelated app or substitute providers. Adapt interaction and layout to desktop and mobile browsers.

`AGENTS.md` is the canonical project guidance. `CLAUDE.md` must remain a relative symlink to `AGENTS.md`, so both tools read the same instructions. The Android repository has its own platform-specific guidance; do not copy its Android build/test commands into this web project.

## Current scope

The root page is a 1:1 port of the Android UI shell, adapted for desktop: navigation (bottom bar, rail from 840px), the map screen (floating search with cookie settings button on phones (Settings sits at the bottom of the desktop navigation rail), cookie "Legközelebbi megálló" location button, draggable departures sheet that docks left on wide screens, map credits chip), search, settings, about, favourites and the planner layout. Theme mode, accent colours, light/dark street maps, Photon place search and opt-in location work. Stops, vehicles, departures, saved favourites, itineraries and offline support are not ported yet: their screens show Android's own empty/status slots with honest "not yet on web" text. Never fill them with fake transit data. Preferences the data ports will read (departure window, nationwide network, local planning providers) already persist in `src/lib/preferences.tsx`. The auth/database scaffold is not the transit backend; its SessionProvider is intentionally not mounted.

UI code: `src/components/app/` (screens, mirroring the Android `ui/` files named in each component's doc comment), `src/components/ui/` (DesignSystem.kt primitives: CookieIconButton, SegmentedItem, ConnectedSelector, ShapeIconTile, dialogs), `src/lib/theme.ts` (Theme.kt colour port), `src/lib/strings.ts` (Hungarian labels copied from Android resources), `src/styles/app.css` (component styles). Material Symbols names used by `<Icon>` must be listed in `src/pages/_document.tsx`.

## Maps and UI

Use **MapLibre GL JS with OpenFreeMap**, the web counterpart to Android's MapLibre Native. Do not use Google Maps. Street styles: `/map/google-light.json` and `/map/google-dark.json`, generated by `scripts/build-google-styles.mjs` from OpenFreeMap Liberty and recoloured to the Android Google basemap (dark road, park, water and rail colours as `map/GoogleBasemapStyle.kt`; unlike Android, dark land cover, buildings and street edges are tinted so the dark map is as detailed as the light one). Like Android's basemap, they leave transit stops and stations off the map (the app draws its own transit data), and they show no road number shields; place badges are drawn in the browser by `src/components/map/style-images.ts` from each style's `bmenetrend:images` metadata, with filled Material Symbols glyphs loaded from Google Fonts. Map text is Google Sans Flex: the script downloads static Regular/Bold files and `OFL.txt` into `public/map/fonts/` and maps Liberty's Noto Sans stacks to them through the style's `font-faces` (Latin and Latin Extended); other scripts still use OpenFreeMap's Noto glyphs. Dark map labels are white rather than Android's `#b9b9b9`. Regenerate them with the script instead of hand-editing. `/map/night.json` is the unchanged Android Night style, kept as reference but not currently used. Follow the app's theme mode (system by default) and preserve the camera when changing styles. Satellite view is intentionally not offered on web. Initial camera is longitude/latitude `[18.825, 47.473]`, zoom `13.2`, maximum zoom `19`.

The copied Night style originates from the Android working tree inspected on 2026-11-15 (HEAD `1f15e9c36346af3c3d8fc63311e04de03c534cf3`). Keep `public/map/licenses/` and `public/map/credits.html` alongside it; retain visible OpenFreeMap, OpenMapTiles and OpenStreetMap attribution. Resources use public URLs, with no map key required.

Use the Android app's Material You / Material 3 Expressive direction and blue fallback colours, rounded surfaces and Hungarian labels. Reuse typed Material Web wrappers from `~/components/material`. Web components and MapLibre must load only in the browser, not during SSR. Preserve keyboard navigation, accessible control names, mobile safe areas and visible attribution. Location is opt-in through its map control.

## Existing backend contracts for future features

- BKK-first Cloudflare Worker: `https://bmenetrend-bkk-proxy.bmenetrend-backend.workers.dev`, configured in Android's `app/build.gradle.kts`. Consult `tools/bkk-worker/README.md` and `data/BkkWorkerClient.kt` for endpoints and response envelopes. BKK credentials stay in Worker secrets, never in browser bundles.
- EMMA GraphQL: `https://mavplusz.hu/otp2-backend/otp/routers/default/index/graphql`, from `data/EmmaParser.kt`; queries and transport in `data/EmmaGraphqlClient.kt` and related repositories.
- Place search: Photon, `https://photon.komoot.io/api/`, from `data/PlacesRepository.kt`.
- Additional local operators retain the sources used in Android. Read their repositories when porting them.

Recheck these contracts before wiring a feature. Preserve provider-scoped identities, timestamps, source labels, bounded viewport requests, request budgets, cancellation and `Retry-After`. A successful empty result is distinct from a failed source. Browser CORS and server-origin access differ from Android: verify support before adding direct calls or a bounded server adapter. Android documents EMMA refusing Cloudflare-origin requests; do not claim full national coverage from the Worker alone. Photon is called directly from the browser (CORS verified); no transit backend calls exist yet.

## Web implementation and checks

Use Bun and the committed `bun.lock`. This is a T3/Next.js Pages Router project with React, TypeScript, Tailwind and tRPC; `src/app/api/auth/` contains the scaffolded auth route. Keep root page code in `src/pages/index.tsx`, map lifecycle in `src/components/map/`, map defaults in `src/lib/map-config.ts`, and theme tokens in `src/styles/globals.css`.

- `bun install`: install dependencies and generate Prisma client.
- `bun run dev`: prepare MapLibre's standalone worker and start development.
- `bun run check`: lint and TypeScript checks.
- `bun run build`: prepare worker and verify production build.
- `bun run db:push`: initialize the optional local scaffold database.

The worker in `public/maplibre/` is generated from the installed MapLibre version and ignored by Git; `scripts/prepare-map-worker.mjs` runs before dev/build. Its URL includes the library version. Clean up maps, observers and event listeners on unmount. Test loading failure/retry and theme changes for map changes; report any runtime/browser verification that could not be performed. Keep secrets, database files, generated clients and build outputs out of Git. Preserve unrelated local work.
